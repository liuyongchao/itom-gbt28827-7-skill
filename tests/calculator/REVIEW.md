# 计算器实现验证记录

本目录只验证 Python 算术辅助程序及其输入控制，不替代技能宿主实际回答测试，也不证明全标准符合性。

- Python 标准库 Decimal，直接导入函数和实际子进程 CLI 均执行。完整输入、输出与逐项断言见 `test-results.json`；可运行 `python tests/calculator/run_regression.py` 复现。
- 合成案例覆盖12种模式、分类费率配对、未知费用、单位、数量和分摊边界、软件综合费率已含项、N01/N02状态传播、单类安全拆合和嵌套拆合、软件跨单位明确换算、四类活动覆盖及有依据裁剪。
- 第一次 CLI 负向测试暴露 Windows 子进程默认本地代码页输出，UTF-8 读取时出现 `UnicodeDecodeError`。已在 CLI 入口显式设置 stdout 为 UTF-8，随后复测通过。这是程序输出编码问题，与标准算术无关。保留此失败和修复记录，未将首次尝试计为通过。
- 另运行 BOM输入、中文文件路径、无效JSON、退出码和复制单个脚本到独立目录的可移植执行检查。

接口审阅确认：未知项没有自动取0或1；单独保留软件已交付且无特殊要求、迁移明确只有一个适用因子的局部规则；生产率方向与费率换算有显式单位合同。错误消息只表明输入合同未满足，不给法定符合性结论。

局限：`non_overlap_confirmed` 和 `composite_rate_confirmed` 等字段是外部审查结论的声明；程序不能验证其真伪。同一实际范围若被人为更换ID、删除问题或伪造非安全domain，无法只凭数字识别。能力卡必须要求保留完整summary及来源登记。四类费用归属、实际基准适用、迁移业务范围、FP外部计数均由上层任务核对。数值使用80位精度且不进行业务货币舍入。

## P2精度接口修复：1.0.1-restricted

独立审查发现：1.0.0的汇总模式错误复用普通人工参数28位数字限制，拒绝自身产生的80位循环小数。已实测复现 `allocation(100×1/3) → total` 和 `software_cost(1人时÷176×10000元/人月) → total` 均返回 `needs_input`。原始输入输出保存在 `precision-reproduction-1.0.0-restricted.json`；旧72项结果保存在 `test-results-v1.0.0-72.json`。旧测试覆盖不足，不能据72项通过认为链路完整。

1.0.1只为汇总条目的 `amount`、`known_subtotal` 增加专用输出解析：最多80位有效数字，展开形式的末尾零不占有效数字限制；数量级指数绝对值≤1024，数值文本≤2048字符，保持有限非负。普通人工参数继续限制28位数字、输入指数绝对值≤100。未改公式、币种舍入或来源边界。

新增13项回归覆盖两个循环小数原样回传、嵌套部分小计、乘法展开的大小数量级、长尾零、超精度/超数量级/过长/负值/非有限值拒绝，以及普通参数仍受28位限制。当前全部 **85/85项通过**；修复后的两条原复现记录在 `precision-reproduction-1.0.1-restricted.json`。这是脚本验证，不替代宿主模型输出测试。
