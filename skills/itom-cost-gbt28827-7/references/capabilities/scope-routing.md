# 运维范围及六类模型选择

## R — 原文与定位

> “硬件设备中如有安全设备应按第9章进行成本度量。”

来源：GB/T 28827.7—2022，7.1，印刷 p.8（PDF 第15页）；六类范围见6.1、7.1、8.1、9.1、10.1、11.1，印刷 p.4、8、12、15—16、19、21。引文是原文，以下路由表与操作步骤为转述。

## I — 方法解释

成本模型首先取决于实际提供什么运维服务，再看服务作用于什么对象。
基础环境涵盖电力、空调、消防等保障信息系统运行的基础设施。
硬件涵盖网络、计算、存储、输入输出及外围设备等；安全设备按明确条款转入安全运维。
软件涵盖基础、支撑及应用软件的运维；软件运维中的适用修改不能一概排除。
安全运维按信息安全目的识别服务，也可能涉及非专用安全软硬件。
管理运维围绕服务人员、过程、技术、资源和交付成果的管理活动。
其他运维承接前述范围未覆盖的迁移、搬迁、云迁移等服务。
同一资产可能承担不同服务；分别列活动、工时与费用归属，才能避免重复归集。
本标准没有给出所有混合项目的唯一自动归类算法；服务边界不明时保留待澄清项。

## A1 — 合成演练

原书未提供该任务的完整案例；以下为合成演练。输入为同一年度合同的七项工作：UPS 巡检、服务器故障支持、防火墙策略维护、现有应用软件维护、服务质量检查、机房设备搬迁、新建一个独立业务系统。

逐项输出：UPS 巡检→基础环境第6章；服务器故障支持→硬件第7章；防火墙策略维护→安全第9章；现有应用维护→软件第8章；质量检查→管理第10章；搬迁→其他第11章；独立新建系统→本次运维范围之外，另列开发任务。安全成本还需继续核对 security-cost 的限定范围，路由成功不表示其全部价格公式均已可执行。

## A2 — 触发场景与近邻区分

- 一份报价混有机房、设备、软件和安全服务，用户要求“先分哪一类运维 / classify maintenance scope”。
- 用户把防火墙或安全网关全部放进硬件台数，要求核对“安全设备怎么归类 / security device routing”。
- 同一软件同时有日常维护、功能修改和另立的新建系统，用户要求“哪些纳入合同 / in-scope services”。
- 搬迁项目包含管理和软件活动，用户要求“拆分服务范围 / mixed service scope”。

本卡只确定对象、服务与模型，不从分类直接生成价格。已确定的分类工作量转 environment-cost、hardware-cost、software-size 或 security-cost；其他迁移转 migration-cost。费用是直接还是间接的问题转 cost-ledger，已经完成的金额合并转 total-review。

## E — 执行契约

**输入**：项目目的；逐项对象、实际服务内容、合同纳入/排除条款；测量周期；混合项目的活动明细。资产名称不能替代服务描述。

1. 建立服务范围表，至少包含 `项号｜对象｜服务活动｜合同依据｜周期`。完成标准：每项服务可被单独解释，未知内容列为“待澄清”。
2. 将明确的活动逐项对应上述六类与第6—11章。安全设备按明示规则转第9章。完成标准：每项有分支或待澄清原因，不能靠名称强行唯一归类。
3. 检查活动是否重复、是否属于独立新增系统开发；检查迁移表1中数据/应用迁移“不含功能变化升级”的局部范围。完成标准：保留范围边界，不把该局部限定扩大为“所有软件运维均不得修改功能”。
4. 输出 `项号｜对象/服务｜适用章节｜纳入/排除/待澄清｜依据｜下一能力`。需分拆时说明分拆依据；不足时请求最少的服务明细后再计算。

完成条件是逐项范围清楚且未知项显式保留，非必须所有项都被强行归入六类。此卡不产生数值，无舍入约定，也没有对应的自动分类计算模式。需要后续计算时先读 CALCULATOR.md，按对应卡选择模式并运行 `python resources/itom_calc.py input.json --out output.json`（从技能根目录执行）。itom_calc.py 只执行已核定输入的计算，不能替代服务范围判断。

## B — 边界与关联

**来源边界**：不提供完整混合服务自动去重算法；本版也不执行全部新建软件开发估价。8.1的软件运维范围与第11章表1的迁移局部范围应分别读取。安全路由不消除多类别安全成本求和疑点 N01。

**实施控制**：按活动建立唯一归属记录、为未明事项保留状态，是防止漏项和重复的执行约定，不冒称标准逐字规定的算法。对象、服务或周期缺失时不继续生成确定报价。

关联：scope-routing 是其他分类计算的前置能力；cost-ledger 处理费用身份；total-review 复核跨分支范围是否重叠。
