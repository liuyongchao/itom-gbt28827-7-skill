# 软件工作量乘综合费率的成本路径

## R — Reading（原文）

> 平均人力成本费率包括运维供方直接人力、间接成本及毛利润。

来源：GB/T 28827.7—2022，8.2.1 注，印刷 p.12（PDF 第19页）。本卡仅实现 8.2.1；8.2.2 的来源口径问题保留为 N02 / S02、S07。

## I — Interpretation（自述）

软件已有工作量后，把每类工作量与同一类的平均人力成本费率配对。
这里的费率是综合费率，结果不能标成纯工资或纯直接人力成本。
逐类相乘再求和，最后加入该项目的直接非人力成本。
费率已经包含的间接成本和毛利润不再外加，相关明细只能用于解释或复核。
人时、人日、人月必须先与费率的分母匹配；本规范案例的 176 不是通用换算值。
缺费率、费率包含范围或换算依据时，先保留工作量和缺口，不生成貌似完整的费用。
本卡不把功能点单价路径与工作量路径相加，也不启用存在来源疑点的 8.2.2。

## A1 — Application Example（合成演练）

原书未提供本卡所示“多类综合费率配对且全部输入已明确”的完整案例；以下为合成演练，并非现实报价或原书案例结果。

同一年度软件运维有 A 类 60 人时、B 类 40 人时。项目确认的综合费率分别为 120 元/人时、180 元/人时，均包含直接人力、间接成本及毛利润；直接非人力费用已完整归集为 800 元。

计算 A 类 `60×120=7,200` 元，B 类 `40×180=7,200` 元，综合费率金额小计为 14,400 元；服务成本为 `14,400+800=15,200` 元。若另见“间接管理费 500 元”且证据表明已包含在上述费率中，它是包含项说明，不再把总额改成 15,700 元。结果是给定输入下的测算，不证明费率为市场公允价。

## A2 — Future Trigger（触发与邻接）

- 已有软件运维工作量，要按报价费率计算费用：“这些人时多少钱 / software effort cost”。
- 多种岗位或软件类别费率不同，要检查配对：“分项人时乘各自单价 / category composite rate”。
- 工作量用人时、价格用人月，要明确换算条件：“人月如何换人时 / hour-to-month conversion”。
- 报价在综合费率外再列间接费用或利润，要检查重复：“是否重复计费 / double counting”。

相邻区分：software-workload 产生工作量；本卡接收工作量后计算费用。cost-ledger 处理四类归属和分摊，本卡检查综合费率已含范围。parameter-evidence 处理费率、换算和参数证据缺口。total-review 汇总不同服务结果，不能把本卡金额再次与其构成项相加。

## E — Execution（执行契约）

**输入。** 必须提供服务范围与周期、分类标识、各类工作量及单位、相应综合费率及单位/出处/包含项、币种、直接非人力金额及完整性。工时与费率不匹配时，另需明确适用于本项目的换算值、方向和依据。零费用必须明确确认；未知不得写成零。

**输出。** 逐类计算表（类别、原工时、转换依据、计价工时、对应费率、乘积）、综合费率金额小计、直接非人力、包含项复核、费用完整性和缺口。缺直接非人力时只输出已知小计；缺工时换算或费率匹配时暂停相应乘积。结果保留来源为 8.2.1。

1. 核定路径。确认输入是已估算工作量与综合费率；若只有 FP 和每 FP 单价，记录 N02，停止该成本分支，不改称 8.2.1。完成标准：选择路径和待算范围明确。
2. 配对并统一单位。工作量必须逐类对应费率。确需换算时使用给定依据，例如“本合同 1 人月=160 人时”才可作 `人时÷160×元/人月`；不得自动使用 176 或 8。完成标准：每个乘积的工时单位相消并得到同一币种。
3. 核对包含项。核实费率含直接人力、间接成本及毛利润；输入只是工资单价或包含范围未明时先补证据。将已含间接明细标作构成说明。完成标准：每项新增金额均未被费率重复包含。
4. 计算 `综合费率金额=Σ(W_i×R_i)`，`服务成本=综合费率金额+直接非人力`。直接非人力可由 nonhuman-cost 取得；未知时显示“已知小计，缺直接非人力”，不得给完整总额。先读 CALCULATOR.md，构造 `mode=software_cost`、`method=8.2.1` 的 JSON，数值使用十进制字符串；通过 `python resources/itom_calc.py input.json --out output.json` 执行。`composite_rate_confirmed=true` 必须来自已核实的包含范围，不是为通过脚本而设置。
5. 交付公式、输入证据、单位及状态。实现约定：中间值保留十进制精度，最终金额按明确约定舍入；无项目另行约定时报告到分并同时保留未舍入值，不能将此称为标准指定精度。完成标准：他人可用同一输入复算，差异仅为披露的显示舍入。

## B — Boundary（边界）

**来源边界。** 8.2.2 注中的“软件开发”口径及表 A.12 经验因子的适用范围尚待核查；即使输入数值可相乘，也不执行此路径。附录的历史费率、176 换算数和区间端点不能自动成为本项目参数。源文件不含当前市场费率，也不提供统一税率；本卡不据此生成税费或市场价结论。

**工程校验。** 拒绝负数、非有限数、类别不匹配和无依据的单位换算；缺项单列，未知不当零。不得把已含间接/毛利润再加一次，不得把一个路径的完整费用当另一路径的附加费。这些是本技能的计算控制，不冒充标准逐字规定。

**关系。** 依赖 software-workload 或外部已核定工作量；缺参转 parameter-evidence；直接非人力转 nonhuman-cost；结果交 total-review，并传递所有未解决状态。
