# 软件规模口径与已计量规模调整

## R — 原文与定位

> “调整后的软件规模＝未调整软件规模×需求蔓延调整因子”
>
> “软件规模＝软件套数×软件级别调整因子×软件类型调整因子”

来源：GB/T 28827.7—2022，8.3.1—8.3.2，印刷 p.13（PDF 第20页）。第一式面向应用软件的已计量规模调整，第二式面向基础、支撑等其他软件。

## I — 方法解释

先区分应用软件与基础、支撑等其他软件，保留各自规模口径。
应用软件宜使用功能点；依据项目特点与估算需要，从所列五种方法选择一种。
本技能接收已核计且可追溯的规模，不提供五种方法的完整计数程序。
已给原始FP规模乘有依据的需求蔓延因子，得到调整后FP规模。
已交付且没有特殊要求时，8.3.1注明需求蔓延因子可取1；这是局部条件规则。
其他软件用套数乘级别、类型两个已定调整因子；级别以中级作基线，类型选一种作基线。
调整后的套数仍是该规模口径，不能改叫FP或直接套每FP的生产率。
通常1至2的需求蔓延范围不是替项目随意选值的授权，附录参数也不是通用定额。

## A1 — 原书案例片段与合成演练

原书附录A.2（印刷p.25—26）案例给出1,000FP，但展开的功能明细有省略，不能仅从显示行重建完整计数；该数在后续例中属于给定输入。原书未提供本卡全部分支的完整可重计案例，下面是明确的合成演练。

已核计的某应用原始规模320FP，已提供所选方法、版本及计数报告；尚未交付，项目数据支持需求蔓延因子1.15，则调整规模368FP。另一个支撑软件范围为3套，已定级别因子1.1、类型因子0.9，调整规模2.97“调整套数”。两者不能相加为370.97FP，也不能用人时/FP生产率处理2.97调整套数。

## A2 — 触发场景与近邻区分

- 用户已经拿到功能点报告，要求“加需求蔓延 / requirements growth adjustment”。
- 用户问已交付软件“还要不要乘蔓延系数 / delivered software size”。
- 基础软件或中间件按套采购，用户要求“套数规模调整 / adjusted software sets”。
- 用户提供按钮数、模块数或附录省略明细，要求“直接算完整FP / function point counting”。此时触发边界解释与依赖清单，不虚构计数。

本卡到规模为止，生产率和三组工作量因子转 software-workload；费率与金额转 software-effort-cost。完整功能点计数需独立的适用计数标准与资料，不能自动使用此前其他版本的NESMA技能代替本文件引用方法。

## E — 执行契约

**输入**：软件类型与范围、周期；应用分支需所选计数方法/版本、外部已核计 S0及单位FP、计数报告来源、交付状态、特殊要求、需求蔓延因子G及依据；套数分支需N、软件级别与类型、各自基线、最终因子L和T及依据。

1. 明确软件类型与本次规模口径。所列功能点入口为COSMIC-FFP、MKⅡ、NESMA、FiSMA、IFPUG，应记录选用的方法及规范版本。完成标准：未把按钮数、页面数或模块数直接标为FP；不能提供可追溯计数结果时停止FP计算，输出N03外部依赖清单。
2. 应用软件核对交付与特殊要求。已交付且无特殊要求可依据8.3.1记录G＝1及条件证据；其他情况必须取得G的项目依据。完成标准：没有将“未提供”当作“无特殊要求”，没有把本局部取1推广到其他参数。
3. 应用分支算 S＝S0×G；其他软件分支算 S＝N×L×T，并保留“调整套数”单位。完成标准：输入与结果均带口径，L和T的基线/依据明确；套数分支缺系数则停止该分支。
4. 输出 `范围｜软件类型｜计数方法/版本｜原始规模｜调整因子及依据｜调整规模｜单位｜外部依赖/缺口`。不同规模口径分开保存，交给下一步时附匹配生产率要求。

**精度约定**：乘法保留精度，不把调整后的FP或套数强制取整；项目有明确舍入规则时另行记录。先读 CALCULATOR.md，以 `mode=software_size` 从技能根目录运行 `python resources/itom_calc.py input.json --out output.json`，按说明选择FP或套数分支。程序不会认证外部FP计数正确性。

## B — 边界与关联

**来源边界**：N03保留完整计数缺口；案例显示的8项合计38FP与给定1,000FP不能据此判为算错，因为明细有省略。本技能不复刻所引五种标准、不声称已校验其完整计数。需求蔓延通常范围及资料性级别/类型系数不成为默认值。

**实施控制**：方法追溯、单位不混、明确交付和特殊要求为执行核对；这些记录不等于外部计数已获法定鉴定。

关联：scope-routing 确定软件服务边界；parameter-evidence 保存因子；software-workload 消费规模与单位。
